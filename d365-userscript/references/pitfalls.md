# 开发中遇到的问题

## 接口和数据

| 现象 | 原因 | 做法 |
|---|---|---|
| `Unexpected end of JSON input`，但操作其实成功了 | 接口成功时返回空内容（204、自定义 API） | 用 `res.text()`，有内容才 `JSON.parse`。报错后先查是否已生成结果，不要直接重试 |
| 脚本判「没有」，实际有 | 没有读取权限：按条件查会被静默过滤成空，直接读返回 403 | 空结果不等于不存在。看对方表上的 Lookup 字段，它的显示值没权限也能读到；UI 上注明「无权限查看」 |
| 接口能提交，页面却认为缺字段 | 必填校验只在表单脚本里 | 把按钮的校验搬进预检查 |
| 新建单金额全是 0 | 服务器插件要等关键字段保存后才取价 | 补字段后重新读取并按新金额检查。确认框里不能显示取价前的金额 |
| 自动填的值不对 | 字段名看起来对，业务含义不同 | 用历史数据验证来源字段，再决定映射 |
| 金额对不上单价 | 有「调整后价格」时金额按它算 | 有效单价 = 调整后价格，没有时才用单价；调整价被填成 0 也是一种情况 |
| 表头和行项状态矛盾 | 接口账号只更新了其中一边 | 两边都读，以能算出来的行项为准，把矛盾显示给用户 |
| 行号排序错乱（10、100、20） | 按字符串排序 | 按数字排序 |
| 大范围统计超时 | 全表聚合太慢 | 缩小到某个业务部门或某一年，或抽样 |
| 外部系统第一页返回 0 条 | 页码从 0 开始 | 用真实请求确认，别假设从 1 开始 |

写 Lookup 用 `<导航属性>@odata.bind`，读用 `_<字段>_value`。导航属性区分大小写，不确定时从 `ManyToOneRelationships` 的 `ReferencingEntityNavigationPropertyName` 查。

按 ID 批量查询时要分块，避免 URL 过长，每块 15 到 40 个。

## 用户脚本环境

| 现象 | 原因 | 做法 |
|---|---|---|
| 加了 `@grant GM_*` 后，iframe 通信、遍历 frames 失效 | ScriptCat 把脚本放进沙箱，`window` 不是真实页面 | 用 `unsafeWindow`（`fetch`、`postMessage`、`sessionStorage`、`frames` 都走它）。不需要 GM 时保持 `@grant none` |
| 跨域 iframe 的数据拿不到 | 同源限制 | 同时 `@match` 两个域，脚本分两半运行，用 `postMessage` 通信；各自用自己的登录 |
| 调外部 HTTP 接口被拦 | 跨域 | `GM_xmlhttpRequest` + `@connect`，首次使用时用户要点允许 |
| 用户反馈与新版本行为不符 | 跑的是旧版或另一份副本 | 先确认用户实际运行的版本。Gist 只有最新版时，差异就出在本地 |
| 面板重复、页面卡死 | 脚本在每个 iframe 里都运行了 | `@noframes`，或判断 `window.top === window.self` |

存储约定：用户配置放 `localStorage`，大量结果放 IndexedDB，密钥放 `GM_setValue`。

## 不得不操作页面时

Web API 做不到才操作页面（上传控件、地图弹窗等）。以下做法都经过实际验证：

- 成功条件是**结果出现**（弹窗打开、状态改变），不是点击完成。D365 卡顿时会吞掉点击。
- 重试前确认没有弹窗在打开或加载，否则会叠开多个窗口。
- 旧版 Web Resource 只监听鼠标事件：依次触发 `mousedown`、`mouseup`、`click`。
- 命令栏要观察到稳定（可见命令连续 2 秒不变）再判断，否则会读到加载中的状态。
- `Xrm.Page` 切单后可能还是上一单的数据：比对它的记录 ID 和 URL 里的 ID。
- 隐藏的旧 iframe 会留在 DOM 里：只用可见且 URL 匹配的。
- 输入后读回控件的值，确认真的写进去了。
- `Xrm` 的 grid API 只能读勾选行，不能设置，要点 DOM 里的勾选框。
- 不可逆点击前先保存「正在提交」状态；中断恢复后要人工核对，不自动重复。
- 同一步最多自动刷新一次，然后停下来说明原因。
- D365 的弹窗只自动关已知无害的那几种，其他业务错误要显示给用户。

## 调用 AI 接口时

- Key 由用户在面板里填，`GM_setValue` 保存，绝不写进脚本。用户把 Key 贴到对话里时也不要写入任何文件。
- 发送前去掉姓名、电话、邮箱、地址等行，提示词要求输出中不出现这些信息。
- Responses API 用 `text: { format: { type: 'json_object' } }` 时，输入里要出现 “json” 这个词，否则接口报错。
- AI 返回的 HTML 按白名单清洗（`p/ol/ul/li/strong/br`），`<script>` 连内容一起去掉。
- 只保存不提交，由用户审核后手动 Submit。

## 导出

- Excel 粘贴用 TSV，单元格内的换行和 Tab 替换掉。
- CSV 里单号按文本写（防止科学计数法、丢前导 0），需要合并单元格时走 HTML 剪贴板。
- `navigator.clipboard` 可能失败，留 `execCommand('copy')` 兜底。

## SharePoint 脚本

CSP 和 AMD 加载器会挡住常规 `<script>` 和 Worker。取回库代码后自行执行，在主线程解析。REST 用 `Accept: application/json;odata=nometadata`，长任务要支持断点（结果放 IndexedDB），连续失败多次时自动停止（多半是登录过期或限流）。
